# Kitmint · Feishu Search Code Connector

用户授权你将指定飞书多维表接入 Kitmint 时执行。只操作用户选定的数据表。接入、字段检查、按钮配置及联调由 AI 连续完成，不将内部测试步骤交给用户。

## 最少打扰
- 复用已提供的表链接、登录状态和授权，不重复询问。不要求用户提供测试口令、SKU、测试行，或替你点击测试按钮。
- 只有缺少目标表链接、需要本人登录/安全输入凭证、权限不足或工具确实无法继续时，才一次性说明具体缺项。能自行检查的信息先检查。
- 用户只提供了一个口令（例如 Groomerbrush）但没有指定行时，不猜产品行、不追问对应 SKU；将其视为业务口令素材保留，接入验收另用独立测试记录。
- 进度只报告有意义的结果或阻塞；结束时简要说明已配置项目和验证结果，不逐项请求确认。遵守宿主工具的必要审批和现有备份规则，但不要自行额外添加确认流程。

## 确认目标
复用用户已经提供的多维表链接；未提供时询问，不能自行选择。链接必须包含 base 与具体 table 参数。自行检查 `search_code` 是否为文本字段，不要求在首列。缺少时直接新增 `search_code` 文本字段，保留其他列及内容。已有同名但类型不兼容的字段时，不擅自转换或覆盖；明确报告冲突。其他名称的口令列先保留，除非用户已明确指定迁移；不拿 SKU 当口令，不修改首列。

## 字段、权限及按钮
1. 检查存在 `search_code` 文本字段，缺少时直接新增。检查「电子指南二维码图片」为附件字段，缺少时自动创建，不删除已有附件列。
2. 确认当前 Kitmint 飞书应用有目标表的读取、修改和附件上传权限；没有权限时指导用户在表格协作/应用权限处授权。不要要求用户交出 App Secret。
3. 添加「生成电子指南二维码」按钮。设置点击当前行按钮触发的自动化：校验当前行 `search_code` 非空，将当前行值作为动态字段引用；禁止写死示例口令。配置完成后自行启用并进行一次完整按钮测试；确认只作用于当前点击行。不要因“尚未测试”一直停在草稿，也不要让用户代点。
4. HTTP 动作：`POST https://ops.kitmint.io/v1/feishu/qr-by-search-code`，请求头 `Content-Type: application/json`，`Authorization: Bearer <表格专属 Key>`，JSON `{ "search_code": "当前行搜索口令的动态引用" }`。不得额外发送 SKU、品牌、设计尺寸、用户 ID 或表格 ID。Key 已绑定表格和生成账号。

## 安全配置 Key
打开 `https://ops.kitmint.io/skills?table_url=<已确认表链接的 URL 编码>`。用户通过飞书登录后只需点击生成按钮，无需重复填写表格链接。生成前后端验证字段和应用权限。

若你的环境支持不向模型暴露输入值、不会记录或截图密钥的安全凭证窗口，打开该窗口让用户输入，并直接绑定到自动化 Authorization 配置。否则先打开飞书 HTTP 动作的 Authorization 输入框，指导用户亲自粘贴；不要假装存在安全窗口。不要将 Key 发到聊天、脚本日志、GitHub 或普通表格单元格。轮换旧 Key 会使旧自动化失效，先告知用户。

## 回写与验收
API 自行生成带口令文字的默认 PNG，并上传、写回 Key 绑定表中同一口令的唯一行。「电子指南二维码图片」该行字段将被替换成最新一张 PNG；其他字段保留。默认二维码区30×30mm，标签总尺寸约30×40mm、600 DPI，长口令增加文字区高度。API 返回业务 JSON，例如 `{"ok":true,"search_code":"EXAMPLE","updated_field":"电子指南二维码图片","width":709,"height":945}`。不要另把 JSON 当图片，不再建立重复上传动作。

### AI 自行完成内部联调
1. 在已选定表内创建专用临时测试行，`search_code` 自行生成唯一值，如 `KITMINT_TEST_日期_随机后缀`，先检查不重名。记录该行的 record_id。若首列必填，可填写“Kitmint 接入测试”；不填充或修改真实 SKU，不借用现有产品行。先检查新增行是否会触发其他业务自动化；如会触发，使用该表支持的隔离测试机制，不冒险触发采购等业务动作。
2. 只在这条测试行点击一次「生成电子指南二维码」，自动查看执行日志，验证本次返回业务 JSON，并检查新 PNG 附件的 token/更新时间和实际下载结果。测试行原来没有附件是正常状态，不是备份失败；“No attachments found”不代表表格备份失败，不为此反复要求用户处理或复制整表。适用的备份规则仍需遵守。
3. 由 AI 解码 PNG，确认 URL 中的 search_code 与测试值一致。具备工具时自行检查目标页面；主站未上线则分别记录“二维码生成/回写已通过”和“消费者页面尚未上线”，不要让用户扫描代测，也不得宣称已经可正式印刷。
4. 完成后仅清理自己创建、且未被他人修改的临时飞书测试行；保留正式字段、按钮及已验证的自动化。Kitmint 侧如无安全删除接口，保留带 `KITMINT_TEST_` 前缀的测试记录，不为清理索要服务器权限或删除业务记录。
5. 遇到限流先退避后重试；最多额外重试一次。重复口令、权限冲突或持续失败时保存具体错误和已完成事项，不循环提问、不重复点击。没有可用的隔离测试方式或必要工具时如实说明未完成的验收项，不能虚报成功。

用户明确指定某条业务记录时才在该行联调；先读取并保留原附件信息，因为 API 会替换该行的输出附件。旧附件不能作为本次成功证据。

401：Key 无效或已轮换；403：权限或组织限制；422：字段缺失/类型错误；429：限流，稍后重试。收到 HTML/Cloudflare 页面或域名无法解析，保存状态码、时间和 Ray ID，交管理员排查 `ops.kitmint.io` 到独立 Kitmint Docker 服务的路由，不要求关闭全站防护。用户无需提供服务器密码或项目源码来使用 API。
